# CLAUDE.md

This file guides Claude Code in this Obsidian vault (a personal engineering second brain). Vocabulary is in `GLOSSARY.md`: use those terms exactly. Say "knowledge note" whenever sources are excluded.

## Layout

- `inbox/` captures (git-ignored); `inbox/processed/` originals of text captures (git-ignored)
- `sources/` (flat) sources; `notes/` knowledge notes (note, topic); `projects/<Name>/<Name>.md` project overviews and justified decision files
- `scripts/kb.py` the only code: `lint`, `search`, `backlinks` (stdlib only)
- `.claude/commands/`: `/ingest`, `/ask`, `/lint`, `/review`, `/maintain`
- `docs/` design, plan and ADRs; `.obsidian/` is app-managed, never edit it; the vault `~/Documents/dev/cowork` is out of scope.

## Rules

- **Metadata.** Every knowledge note and source has `type`, `created`, `updated` (`YYYY-MM-DD`). A Markdown source also has `sha256` (of the original's bytes) and `original`, a valid basename written double-quoted. For a text source `original` is the processed name of its original and is never checked for existence (`inbox/processed/` is not in git). For a companion source (the Markdown record of a binary capture) it is the exact filename of the binary in `sources/`; lint verifies the file exists, is not Markdown and has the same sha256. A binary needs no separate original file. Only the YAML subset in the design doc is allowed; quote wikilinks in values. Never add frontmatter to an existing file except through `/maintain` with an approved diff.
- **Basename rule.** Non-empty, at most 255 UTF-8 bytes, not exactly `.` or `..` (a name merely containing `..` is fine), no `/`, `\` or `:`, no drive-letter prefix, no leading or trailing whitespace (Unicode White_Space), no trailing `.`, no control characters, no bidirectional override or isolate characters (U+202A to U+202E, U+2066 to U+2069). Preserve Unicode; compare NFC-normalized and case-insensitively.
- **`updated`** is the date of the last knowledge-text or link change (including conflict callouts, progress entries and `sources:` edits). It does not move for whitespace, formatting, or metadata-only edits (`tags`, `aliases`, `confidence`, `standalone`). A source's `updated` always equals its `created`.
- **Names.** Knowledge notes use human titles; sources use kebab-case (lowercase, runs of non-letters/digits become `-`, Unicode letters kept, `capture-<8 hex>` if empty); project folder and overview use the project name. Never use `# ^ [ ] |` in a filename. Basenames are unique across the vault. Check collisions before creating a file; a collision suffix `-<8 hex of sha256>` goes before the extension. Never overwrite or rename an existing file. Processed name: `YYYY-MM-DD-<capture name>` with `/ \ :`, control and bidi characters replaced by `-`, trimmed, truncated to fit 255 bytes.
- **Links.** Bare wikilinks. Cite as `[[Note]]` or `[[Note#Heading]]`, and only headings you have read. Technology relationships are links; tags are optional filter facets.
- **Resume is deterministic and has no manifest.** Every contribution a capture makes to a knowledge note (new note, update, progress entry, conflict callout) cites its source with a wikilink (or `sources:` in a new note). A capture that has a source but is not finalized is resumed by re-reading the source, reconstructing the expected contributions, and checking each target independently: a contribution is *present* only if its target cites the source there and contains the content; *missing* if it does not cite the source; otherwise *unclear*. Apply only the missing ones. If anything is unclear, or the contributions cannot be reconstructed reliably, ask the user and write nothing for it. Every knowledge note that cites the source must map to a reconstructed contribution; one that does not (renamed, or reconstructed differently) makes it unclear, never missing. A backlink alone is never proof. Resume lint for a binary capture uses `--pending <planned filename>` so that only the one target left by a verified rollback is tolerated.
- **Unresolved errors are never baseline.** Validation passes only if no new ERROR and no new W10 appears anywhere and no ERROR, W10 or E07 exists in any file the capture created in any attempt. On a retry, any ERROR, W10 or E07 in the capture's own files (source, companion, notes citing the source, notes whose conflict callout cites those) stops that capture and directs the user to `/maintain`; a pre-existing knowledge note's error stops it too, because the two cannot be told apart. For E07 `/maintain` names file and line only, shows no diff, and the user edits by hand. Never delete or roll back knowledge notes to clear an error.
- **Additive by default.** Ingest never rewrites or deletes existing text. Consolidation, correction, restructuring, conflict resolution, metadata completion, companion repair and source recovery go through `/maintain` as a diff that waits for approval. Source recovery: candidates are the original in `inbox/processed/` or the capture still in `inbox/`; the candidate's sha256 must equal the source's stored `sha256` (never derive that hash from the candidate); the candidate must have no W07 finding; build and `cmp` the replacement first; show the diff; write only after approval naming the source file; re-hash the candidate and the target immediately before the write; on any failed verification write nothing and never overwrite.
- **Sources are not knowledge.** Never edit a source body, except through approved `/maintain` source recovery, and never add a conflict callout to a source. Keep what a source says apart from what the user knows, and say which one you cite.
- **Knowledge notes only for reusable knowledge or learning progress.** Many captures end as a source. Progress goes under a dated `## Progress` section of the topic note: the explicit event or completion date stated in the capture, else the ingestion date. Create a topic note for progress only for a meaningful subject that warrants ongoing tracking, never for a trivial, isolated activity. No learning log, no progress type.
- **Decisions and lessons.** A separate decision file only with real alternatives and reusable rationale; otherwise a bullet in the project overview. Reusable lessons go to `notes/`; project-specific ones stay in the overview.
- **Conflicts.** Both claims in knowledge notes: a `> [!warning] Conflict` callout in **both**, each citing the other and the source of the claim it adds, or in neither. Sequence (ingest and `/maintain`): snapshot both notes and dirty-tree-check them; if either is dirty and unapproved or changed since its snapshot (a note this run already wrote: since its last recorded hash, which stops the run), write neither. Otherwise record the first note's hash, edit it, record its new hash, verify the second's hash, edit the second. If the second step fails, undo the first only if its hash still equals the recorded post-edit hash (exact reverse edit, then verify against the pre-edit hash); if the first note changed or the undo cannot be verified, stop the run and report the one-sided callout. One claim only in a source: a single callout in the knowledge note citing the source; record the source file's content hash before and verify it after. A **skipped conflict** is never called resolved: list both note paths (or note and source) and the reason under **Needs attention** in the final report, say it still requires attention, and create no marker in the vault unless the user explicitly approves one.
- **Stale** means a human should review it, not that it is wrong. Orphan, stale and old-capture findings never block ingestion or trigger edits, deletion or archiving.

## Safety

- **Secrets.** Run `python3 scripts/kb.py lint --json` before opening a capture. A suspicious capture is blocked alone; other captures continue. Never print, redact, delete or modify matched content; the user clears a false positive by editing or removing it. Regex scanning is a safety net only and cannot see undecodable files.
- **Classification.** Text capture = `.md` or `.txt` (extension case-insensitive) that is valid UTF-8: a source copy (`.md`, body verbatim; a `.txt` is not Markdown and is never reflowed) plus an original in `inbox/processed/`. Everything else is binary, including UTF-8 `.json`/`.csv`/`.html`, `.markdown` and a non-UTF-8 `.txt`: not parsed as Markdown, moved as-is into `sources/` with no copy, secret-scanned only when it decodes as UTF-8 (a non-UTF-8 `.txt`, PDFs, images and archives are never scanned), and it contributes knowledge only through notes you write that cite its planned filename. A non-UTF-8 `.md` is blocked: stop that capture, ask, never convert its encoding. An extension-less file and an empty capture are blocked; a symlink is skipped and reported.
- **Failure isolation.** *Isolated* (that capture, or only the dependent part; continue): suspected secret, non-UTF-8 `.md`, empty, extension-less, symlink or unreadable capture, a created name that still violates the basename rule, duplicate, corrupt source, a retry whose planned filename is taken, a not-yet-written target that was dirty or changed since its snapshot, capture changed after hashing, a skipped conflict (including a verified undo), a post-move validation failure whose rollback verified, validation failure confined to the capture's own writes (the capture is then not finalized), a retry that finds an unresolved ERROR, W10 or E07 in the capture's own files. When any knowledge part is skipped the capture is **not finalized**: it stays in `inbox/` as partially ingested and a later run resumes it. *Run-level* (stop everything, clean up nothing, report completed, failed and pending captures, every file written and every Needs attention entry so far): lint cannot run or exits 2; a file this run already wrote (a conflict partner included) or the snapshot file changed since its last recorded hash; a failed or partial write, move or verification (including snapshot, disk, permission or `git status` errors); a failed or unverifiable rollback or undo; a new ERROR or new W10 outside the files written for the current capture. `/maintain` and the `/ask` save are single operations: any failed write or verification stops them with a report.
- **Dirty-tree rule (every write).** Before the first write of a run and whenever a new target appears, record into a snapshot file in the session scratchpad (not in the vault) `git status --porcelain` for the target and its sha256 (or "absent"). Targets: every file you will create, edit or move, conflict partners and the capture included. A target already modified, staged or untracked and not written by this run is never touched without explicit approval naming that file; offer a checkpoint commit, never make one unprompted. After you write a file record its new sha256 and verify it before any further change to it. Existing knowledge notes get exact-string edits only. Never use reset, checkout --, restore, clean, stash, rebase or force options.
- **Reports.** After any write list every file created, edited or moved, every blocked capture with its reason and a **Needs attention** section (skipped conflicts, new E07, baseline errors left alone), then offer a checkpoint commit. Approval requests list every dirty or untracked target so one approval can name them.

## Commands

Run `python3 scripts/kb.py <lint|search|backlinks> --help` for flags. Lint levels: ERROR (exit 1), WARNING, REVIEW, and PENDING (only with `--pending`).
